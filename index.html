1. はじめに - Donuts Chat とは

Donuts Chat は、Amazon Bedrock AgentCore を活用した高機能な AI エージェントチャットアプリケーションです。複数の AI モデルやエージェントを選択して、様々なタスクを効率的に実行することができます。

主な機能

🤖 マルチエージェント対応

複数の専門エージェントを選択して、それぞれの得意分野に応じたタスクを実行できます。

🧠 複数AIモデル

Claude、Nova など複数の AI モデルから用途に応じて選択できます。

🔍 高度な検索機能

チャット履歴、エージェント、ツールを素早く検索できます。

📎 画像添付

画像を添付してAIに分析させることができます。

2. ログイン・ログアウト

ログイン方法

1 ログインページにアクセス

ブラウザで Donuts Chat の URL にアクセスします。以下のようなログイン画面が表示されます。

2 ユーザー情報を入力

以下の情報を入力してください：

  • Username: 管理者から提供されたユーザー名
  • Password: 管理者から提供されたパスワード
3 サインインボタンをクリック

「Sign In」ボタンをクリックしてログインします。認証が成功すると、メインのチャット画面に遷移します。

💡 ヒント：アカウントの新規作成

アカウントをお持ちでない場合は、「Sign Up」リンクをクリックして新規登録を行ってください。

ログアウト方法

1 ユーザーメニューを開く

サイドバーの下部にあるユーザー名ボタンをクリックします。

2 Sign Out をクリック

表示されたメニューから「Sign Out」をクリックするとログアウトできます。

3. チャット機能の使い方

メイン画面の構成

ログイン後のメイン画面は以下の要素で構成されています：

エリア 説明
サイドバー（左） ナビゲーションメニューと過去のチャット履歴が表示されます
メインエリア（中央） チャットのメッセージが表示されるエリアです
入力エリア（下部） メッセージの入力、エージェント選択、モデル選択を行います

新しいチャットを開始する

1 New Chat をクリック

サイドバーの「New Chat」をクリックして新しいチャットを開始します。

2 メッセージを入力

画面下部の入力欄（「Type your message...」）にメッセージを入力します。

3 送信

Enter キーを押すか、送信ボタンをクリックしてメッセージを送信します。AI からの応答がリアルタイムで表示されます。

画像を添付する

1 添付ボタンをクリック

入力欄の横にある「Attach image」ボタンをクリックします。

2 画像を選択

ファイル選択ダイアログから添付したい画像を選択します。

3 メッセージと共に送信

画像について質問や指示を入力して送信すると、AI が画像を分析して回答します。

過去のチャットを続ける

サイドバーには過去のチャット履歴が一覧表示されます。続きを話したいチャットをクリックすると、そのチャットを再開できます。

4. AIエージェントの選択

Donuts Chat では、複数の専門 AI エージェントから用途に応じたエージェントを選択できます。

エージェントを選択する

1 エージェント選択エリアを確認

画面下部の入力欄の上に、現在選択中のエージェントが表示されています。

2 全エージェント表示ボタンをクリック

「...」ボタンをクリックすると、利用可能なすべてのエージェントが表示されるモーダルが開きます。

3 エージェントを検索・選択

検索ボックスでエージェントを検索するか、一覧から使用したいエージェントをクリックして選択します。

エージェント名 用途
Multi-Agent Orchestrator 複数のエージェントを統合して複雑なタスクを処理
Comprehensive Research Report 詳細なリサーチレポートの作成
Project Execution プロジェクトの実行と管理
Content Creation Pipeline コンテンツ作成ワークフロー

新しいエージェントを作成する

Donuts Chat では、独自の AI エージェントを作成して、特定のタスクに最適化したアシスタントを構築できます。

1 Create New Agent をクリック

エージェント選択モーダルの「Create New Agent」ボタンをクリックして、エージェント作成フォームを開きます。

Basic Settings（基本設定）

項目 必須 説明
Name & Icon ✓ エージェントの名前とアイコン。アイコンをクリックして絵文字を選択できます
Description エージェントの説明文。何ができるかを簡潔に記載します

💡 ヒント：Auto-generate with AI

名前と説明を入力すると「Auto-generate with AI」ボタンが有効になり、AIが自動的にシステムプロンプトを生成してくれます。

システムプロンプトの書き方

システムプロンプトは、AIエージェントの性格、能力、制約を定義する最も重要な要素です。効果的なシステムプロンプトを書くためのポイントを紹介します。

1. 役割と専門性を明確に定義する

エージェントが「誰」であり、「何の専門家」かを明確にします。

あなたは AWS のソリューションアーキテクトです。
クラウドアーキテクチャの設計、コスト最適化、
セキュリティベストプラクティスについてアドバイスを提供します。

2. 具体的な行動指針を記載する

エージェントがどのように行動すべきかを具体的に指示します。

## 行動指針
- ユーザーの質問には必ず根拠を示して回答する
- 不明な点がある場合は、推測せずに確認の質問をする
- 複雑な問題は、段階的に分解して説明する
- コードサンプルを提示する際は、コメントを付ける

3. 出力フォーマットを指定する

回答の形式や構造を指定することで、一貫性のある出力を得られます。

## 出力フォーマット
回答は以下の構造で提供してください：
1. 概要（3行以内）
2. 詳細説明
3. 具体例やサンプルコード
4. 注意点やベストプラクティス

4. 制約や禁止事項を明記する

やってはいけないことを明確にすることで、安全性と品質を確保します。

## 制約事項
- 機密情報や個人情報を推測して回答しない
- 確証のない情報を事実として伝えない
- ユーザーが明示的に許可していない操作を実行しない

⚠️ システムプロンプト作成のベストプラクティス

  • 簡潔さと具体性のバランス: 長すぎると処理が遅くなり、短すぎると曖昧になります
  • Markdown形式を活用: 見出し（##）や箇条書き（-）で構造化すると読みやすくなります
  • テストと改善: 作成後は様々なパターンでテストし、必要に応じて調整します
  • 言語の統一: プロンプトを英語で書くと、より安定した動作が期待できます

シナリオの追加

「Add Scenario」ボタンをクリックすると、ユーザーがワンクリックで実行できる定型タスクを追加できます。

項目 説明
タイトル シナリオの名前（ボタンに表示されます）
プロンプト クリック時に自動送信されるメッセージ

💡 ヒント：シナリオの活用例

  • 「日次レポートを作成」
  • 「コードレビューを開始」
  • 「週次サマリーを生成」
  • 「新しいプロジェクトをセットアップ」

Tools（ツール設定）

「Tools」タブでは、エージェントが使用できるツール（外部機能）を選択します。

利用可能なツールは検索ボックスで絞り込めます。必要なツールにチェックを入れて選択してください。

💡 ヒント：ツール選択のコツ

  • 必要最小限のツールを選択: 多すぎるツールはAIの判断を複雑にします
  • タスクに関連するツールのみ: エージェントの目的に直接関係するツールを選びましょう
  • ツールの説明を確認: 各ツールの機能を理解してから選択してください

⚠️ ツール一覧が表示されない場合

Toolsタブを開いてもツール一覧が表示されない場合は、以下をお試しください：

  • ページをリロード（F5キーまたはブラウザの更新ボタン）してから再度お試しください
  • 一度ログアウトしてから再度ログインしてください
  • しばらく待ってからToolsタブを再度クリックしてください

ツール一覧が読み込まれていない状態でエージェントを保存すると、ツールが正しく設定されない場合があります。

主要なツールカテゴリ
カテゴリ ツール例 用途
Web検索 tavily_search, tavily_extract 最新情報の取得、Webページの解析
ファイル操作 file_editor, s3_list_files ファイルの作成・編集、S3操作
コード実行 execute_command, code_interpreter シェルコマンド実行、Python実行
AWS操作 aws_cli AWSリソースの操作・調査
エージェント連携 call_agent, create_agent 他のエージェントの呼び出し・作成

⚠️ ツール利用の注意点

  • execute_command: シェルコマンドを実行できるため、慎重に使用してください
  • file_editor: ファイルを作成・変更できるため、作業ディレクトリを適切に設定してください
  • aws_cli: AWS リソースを操作できるため、IAM権限を確認してください

MCP（Model Context Protocol）設定

「MCP」タブでは、外部のMCPサーバーと連携するための設定を行います。MCPは、AIモデルに追加のコンテキストやツールを提供するためのプロトコルです。

「Insert Sample」ボタンをクリックすると、事前定義されたMCPサーバー設定のサンプルを挿入できます。

サンプル 説明
Filesystem Server ローカルファイルシステムへのアクセスを提供
GitHub Server GitHubリポジトリの操作機能を提供
AWS Documentation Server AWSドキュメントの検索・参照機能を提供
Multiple Servers 複数のMCPサーバーを同時に設定する例

💡 ヒント：MCP活用のポイント

  • Preview Tools: 設定後に「Preview Tools」ボタンで、実際に利用可能になるツールを確認できます
  • JSON形式: MCP設定はJSON形式で記述します
  • サンプルを活用: まずはサンプルを挿入して、必要に応じてカスタマイズしましょう
2 エージェントを保存

すべての設定が完了したら、「Save」ボタンをクリックしてエージェントを保存します。保存したエージェントはすぐに利用可能になります。

⚠️ エージェント作成時の注意

  • システムプロンプトは必須項目です
  • ツールを選択しない場合、エージェントは会話のみ可能になります
  • 作成したエージェントは後から編集・削除できます

8. イベント連携

Event Integration 機能を使用すると、スケジュールや外部イベント（S3へのファイルアップロード、CloudWatch アラームなど）をトリガーとして、AIエージェントを自動実行できます。定期的なレポート生成、データ収集、障害検知時の自動調査など、様々な自動化シナリオを実現できます。

イベント連携ページを開く

1 Event Integration をクリック

サイドバーの「Event Integration」をクリックします。

イベント連携の一覧画面では、以下の情報を確認できます：

項目 説明
トリガー名 設定したトリガーの名前と説明
有効/無効スイッチ トリガーの有効・無効を切り替え
イベントソース スケジュールまたは外部イベントの種類
実行エージェント トリガー発火時に実行されるAIエージェント
最終実行日時 最後にトリガーが実行された日時

新しいトリガーを作成する

1 Create New ボタンをクリック

画面右上の「Create New」ボタンをクリックして、新規トリガー作成モーダルを開きます。

基本設定（Basic Settings）

2 基本情報を入力

以下の情報を設定します：

  • Trigger Name（必須）: トリガーの名前（例：「Daily Report Generation」）
  • Agent to Execute（必須）: 実行するAIエージェントを選択
  • Description: トリガーの目的や説明
  • Model ID（オプション）: 使用するAIモデル（未指定の場合はエージェントのデフォルトモデルを使用）
  • Working Directory（オプション）: エージェントの作業ディレクトリ
  • Prompt: エージェントに送信するメッセージ

トリガー設定（Trigger Configuration）

3 トリガータイプを選択

「Trigger Configuration」タブで、トリガーの種類を選択します。

トリガータイプ 説明 用途例
🕐 Schedule 指定したスケジュールで自動実行 日次レポート、週次バックアップ、定期的なデータ収集
⚡ Event-Driven 外部イベント発生時に実行 S3へのファイルアップロード、CloudWatchアラーム、エラーログ検出

スケジュール設定

「Schedule」を選択した場合、実行タイミングを設定できます。

プリセットスケジュール：

  • Every Minute - 毎分実行
  • Every Hour - 毎時実行
  • Every Day (00:00) - 毎日深夜0時に実行
  • Every Weekday - 平日のみ実行
  • Every Monday - 毎週月曜日に実行
  • 1st of Every Month - 毎月1日に実行
  • Custom - Cron式でカスタム設定

💡 ヒント：タイムゾーン設定

スケジュールは選択したタイムゾーン（デフォルト: Asia/Tokyo）に基づいて実行されます。必要に応じてタイムゾーンを変更してください。

イベント駆動設定

「Event-Driven」を選択した場合、利用可能なイベントソースから選択します。

利用可能なイベントソース（例）：

  • S3 File Upload - 指定パターンに一致するファイルがS3にアップロードされた時
  • CloudWatch Alarm - CloudWatchアラームの状態が変化した時
  • Error Log Detection - アプリケーションのエラーログが検出された時
  • GitHub Issue Created - GitHubで新しいIssueが作成された時

💡 ヒント：EventBridge Rule Details

各イベントソースの「EventBridge Rule Details」を展開すると、Amazon EventBridgeのルール詳細を確認できます。システム管理者が事前に設定したイベントルールから選択できます。

4 保存

設定が完了したら「Save」ボタンをクリックしてトリガーを保存します。

実行履歴を確認する

各トリガーの「Execution History」ボタンをクリックすると、過去の実行履歴を確認できます。

項目 説明
Status 実行状態（completed, failed など）
Started At 実行開始日時
Completed At 実行完了日時
Duration 実行にかかった時間
Execution ID 実行を一意に識別するID

トリガーの管理

各トリガーカードには以下の操作ボタンがあります：

  • トグルスイッチ - トリガーの有効/無効を切り替え
  • Edit - トリガー設定を編集
  • Execution History - 実行履歴を表示
  • Delete - トリガーを削除

⚠️ 注意

トリガーを削除すると、関連する実行履歴も削除されます。削除前に必要な情報を確認してください。

10. よくある質問

Q: ログインできない場合は？

以下を確認してください：

  • ユーザー名とパスワードが正しいか
  • Caps Lock がオフになっているか
  • パスワードの大文字・小文字が正確か

問題が解決しない場合は、管理者にお問い合わせください。

Q: チャット履歴を削除するには？

サイドバーのチャット一覧から、削除したいチャットにマウスを合わせると表示される削除ボタンをクリックしてください。

Q: 応答が遅い場合は？

  • より軽量なモデル（Claude Haiku や Nova Lite）を選択してみてください
  • ネットワーク接続を確認してください
  • ブラウザを再読み込みしてみてください

Q: 対応している画像形式は？

PNG、JPEG、GIF、WebP 形式の画像に対応しています。

Q: セッションが切れた場合は？

長時間操作がない場合、セキュリティのためセッションが切れることがあります。再度ログインしてください。過去のチャット履歴は保持されています。
